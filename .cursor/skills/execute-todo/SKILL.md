# Выполнение TODO после проверки задания

Эта команда — часть самостоятельного обучения. Пользователь своими словами формулирует, что нужно сделать, а навык проверяет, что выполнение этого задания и есть выполнение TODO. Навык не формулирует задание за пользователя.

## Входные данные

После команды пользователь передаёт задание в свободной форме. Считай весь текст после `/execute-todo` проверяемым заданием.

## Обязательный порядок

### 1. Исследовать задачу

До оценки задания:

1. Определи, о каком TODO идёт речь, и найди связанный с ним код.
2. Прочитай `руководства/задание-1/README.md`, соответствующую часть руководства, правила проекта, открытые тесты и соседний код.
3. Установи место TODO в последовательности учебных частей и проверь, выполнены ли необходимые предыдущие этапы.
4. Установи текущее поведение, требуемый результат и сценарии проверки, которые руководство приводит для этого TODO.
5. Не изменяй файлы и не выполняй команды с побочными эффектами на этом этапе.

### 2. Проверить задание

Задание пригодно при единственном условии: своими словами и по смыслу оно описывает работу, выполнение которой равно выполнению одного TODO.

- Форма и структура не важны. Не требуй перечислять файлы, запреты, договор поведения или способ проверки.
- Неточные формулировки, другие названия и пропущенные подробности допустимы, если суть TODO передана верно.
- Голая ссылка на номер TODO («выполни TODO 1.1.a») без описания сути непригодна.
- Непригодно задание, которое описывает другую работу, шире одного TODO (например, «сделай всю часть 1») или только часть TODO.

### 3. Выбрать один исход

#### Задание пригодно

1. Кратко сообщи, почему задание соответствует TODO.
2. До изменения объясни цель, договор поведения, затрагиваемые файлы и способ проверки.
3. Выполни TODO полностью. Границы, которых нет в задании, соблюдай сам: разрешённые и запрещённые файлы из раздела о границах практической работы в соответствующей части руководства, правила проекта, неизменность предоставленных блоков вроде `finally`, отказ от соседних TODO.
4. Проведи проверки. Обязательно запусти сценарии проверки из раздела руководства для этого TODO, если они есть, и приведи их фактический вывод. Не меняй файлы сценариев и тесты ради прохождения. Порождённый моделью код запускай только в разрешённой правилами проекта изолированной среде.
5. Сообщи:
   - что изменено;
   - какие проверки выполнены;
   - фактический результат проверок;
   - оставшиеся ограничения или риски.

Не останавливайся после анализа и не проси дополнительного подтверждения, если задание пригодно.

#### Задание непригодно

Не изменяй файлы и не начинай реализацию. Ответь в таком виде:

```markdown
Задание пока не соответствует TODO.

Расхождения:
- [что в задании не совпадает с TODO: другая работа, шире TODO, только часть TODO или нет описания сути]
  - Почему это важно: [что было бы сделано не так или не сделано]

Вопросы для самостоятельной корректировки:
- [наводящий вопрос, который помогает пользователю самому восполнить конкретное расхождение]
```

Не составляй, не дописывай, не перефразируй и не показывай исправленное задание или его готовые фрагменты. Объясняй расхождения на материале найденного TODO и соответствующего раздела руководства. Не давай общих замечаний вроде «добавьте больше подробностей».

## Запреты

- Не объявляй задание пригодным без изучения связанного кода.
- Не подменяй выполнение TODO только планом или примером кода.
- Не расширяй задачу сопутствующей переработкой, не нужной для TODO.
- Не считай собственное утверждение об успехе доказательством: опирайся на изменения и воспроизводимые проверки.
