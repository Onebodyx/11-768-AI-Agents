## 2. Два мира, которые нельзя смешивать



### Windows-хост

На Windows выполняются:

- PowerShell-команды пользователя;
- `uv`, командные точки задания и клиент OpenAI;
- `llama-server.exe`;
- управление Docker;
- запись местных патчей, траекторий и результатов.

**Командная точка задания** — установленная вместе с проектом команда наподобие `assignment-doctor` или `assignment-play-chess`. `uv run` запускает её в закреплённой среде Python проекта; пользователю не требуется знать внутренний файл, в котором она реализована.

Модель доступна только по адресу:

> ```text
> http://127.0.0.1:8080/v1
> ```



### Linux-контейнер

В контейнере выполняются:

- команды, которые CodeAgent передаёт в `Environment.execute`;
- работа с `/testbed`;
- проверки приложения;
- `sandbox_python.py` и любой Python, созданный моделью;
- шахматная служба.

Команды Linux в этом руководстве встречаются только как описание действий агента внутри контейнера. Пользователь не должен запускать их в PowerShell.

```text
PowerShell пользователя
    ├── llama-server.exe на 127.0.0.1:8080
    ├── каркас Agent и клиент API
    └── Docker Desktop
          └── эфемерный Linux-контейнер
                ├── /testbed
                ├── команды execute
                └── sandbox_python.py
```

Главное правило: порождённый моделью код никогда не исполняется непосредственно в Windows.

## 3. Как устроена местная песочница

Адаптированный `assignment-1` уже содержит Docker-конструктор. Его не нужно реализовывать в учебных TODO.

Один запуск создаёт отдельный контейнер со следующими свойствами:

- образ Linux/amd64;
- рабочий каталог приложения `/testbed`;
- сеть `bridge`;
- нет bind mount каталогов хоста;
- нет сокета Docker;
- нет домашнего каталога пользователя;
- нет `.env` и иных секретов;
- нет переданных устройств;
- `cap-drop=ALL`;
- `no-new-privileges:true`;
- `--init`;
- `--rm`;
- не более 512 процессов;
- не более 8 CPU;
- не более 8 GiB RAM и столько же совокупной RAM с подкачкой;
- внутренний порт публикуется только при необходимости;
- наружный порт выбирается Docker случайно;
- привязка наружного порта — только `127.0.0.1`;
- контейнер помечается отдельным идентификатором сессии;
- пользовательские `argv` и `env` обычного `exec` передаются JSON-ом через stdin контейнерному исполнителю и не попадают в аргументы `docker.exe`;
- штатный `with`/`finally` немедленно останавливает и адресно удаляет контейнер;
- если управляющий процесс оборван, `--rm` удаляет контейнер после `deployment_timeout`, когда его `sleep` завершится и демон Docker доступен.

Назначение основных ограничений:

- сеть `bridge` отделяет сеть контейнера от Windows; наружу публикуется только явно разрешённый порт;
- `cap-drop=ALL` удаляет дополнительные возможности ядра Linux;
- `no-new-privileges:true` запрещает процессам получать новые привилегии;
- `--init` добавляет небольшой начальный процесс, который передаёт сигналы и убирает завершившиеся дочерние процессы;
- `--rm` просит Docker удалить контейнер после его остановки;
- `deployment_timeout` задаёт предельное время жизни контейнера и страховочный момент остановки;
- передача `argv` и `env` через стандартный ввод не помещает пользовательские значения в командную строку процесса Docker на Windows.

Исходный код приложения не монтируется внутрь. Конструктор:

1. проверяет, что местный `chess_app` находится на базовом коммите задачи и не содержит незакоммиченных правок;
2. создаёт временный контекст сборки;
3. исключает `.git`, `.venv`, `.pytest_cache`, `__pycache__`, `.env` и `*.pyc`;
4. собирает местный образ;
5. запускает чистый контейнер;
6. при необходимости применяет переданный патч уже в `/testbed`.

Это защищает опыт от ложного успеха на заранее изменённой рабочей копии.

## 5. Настройка `.env`

API принадлежит только местному серверу. Значение ключа нужно клиенту SDK как непустая строка, но сервер не использует его как секрет.

Создайте или замените `.env` для основной Qwen:

```powershell
$utf8WithoutBom = [System.Text.UTF8Encoding]::new($false)
$envPath = [System.IO.Path]::GetFullPath((Join-Path -Path (Get-Location) -ChildPath '.env'))
$envLines = @(
  'OPENAI_BASE_URL=http://127.0.0.1:8080/v1'
  'OPENAI_API_KEY=local-dummy'
  'OPENAI_MODEL=Qwen3.6-27B-Q6_K'
  'OPENAI_MAX_RETRIES=5'
)
[System.IO.File]::WriteAllLines($envPath, $envLines, $utf8WithoutBom)
```

В Windows PowerShell 5.1 режим `utf8` у `Set-Content` добавляет BOM, который некоторые разборщики принимают за часть первого ключа или JSON, поэтому текстовые настройки и JSON ниже записываются через `UTF8Encoding($false)`.

Назначение полей:

- `OPENAI_BASE_URL` — единственная местная конечная точка, обязательно с путём `/v1`;
- `OPENAI_API_KEY=local-dummy` — несекретное служебное значение;
- `OPENAI_MODEL` — точный псевдоним, который должен присутствовать в `/v1/models`;
- `OPENAI_MAX_RETRIES` — число повторов временного сбоя.

Не печатайте `.env` в терминал и не передавайте его модели. Убедитесь, что файл не попадёт в Git:

```powershell
git check-ignore .env
git status --short -- .env
```

Первой командой ожидается путь `.env`. Вторая не должна показывать файл как новый или изменённый для фиксации.

При переходе на GPT-OSS замените только псевдоним:

```powershell
$utf8WithoutBom = [System.Text.UTF8Encoding]::new($false)
$envPath = [System.IO.Path]::GetFullPath((Join-Path -Path (Get-Location) -ChildPath '.env'))
$envText = [System.IO.File]::ReadAllText($envPath, [System.Text.Encoding]::UTF8)
if ($envText -notmatch '(?m)^OPENAI_MODEL=') {
  throw 'В .env нет строки OPENAI_MODEL.'
}
$envText = $envText -replace '(?m)^OPENAI_MODEL=.*$', 'OPENAI_MODEL=gpt-oss-20b-MXFP4'
[System.IO.File]::WriteAllText($envPath, $envText, $utf8WithoutBom)
```

Не меняйте модель в `.env`, пока сервер с прежней моделью ещё работает.

## 6. Запуск основной Qwen

Откройте отдельное окно PowerShell. Аргументы оформлены массивом, чтобы пути и параметры передавались без неоднозначного разбора.

Основные параметры профиля:

- `--jinja` применяет шаблон диалога, встроенный в модель;
- `--reasoning-format auto` и `--reasoning on` включают поддерживаемое моделью оформление рассуждения;
- `--ctx-size 32768` задаёт окно контекста в токенах;
- `--parallel 1` разрешает один запрос одновременно;
- `--cache-type-k` и `--cache-type-v` задают формат KV-кэша;
- `--flash-attn on` включает оптимизированное внимание;
- `--n-gpu-layers auto` размещает на GPU столько слоёв, сколько позволяет профиль;
- `--fit on` и `--fit-target 256` подгоняют размещение под доступную видеопамять с заданным целевым запасом;
- `--no-mmproj`, `--no-webui` и `--no-agent` отключают ненужные для задания мультимодальный проектор, веб-интерфейс и встроенный агентный режим сервера;
- `--offline` запрещает серверу самостоятельно получать внешние материалы.

```powershell
$qwenArgs = @(
  '--model'; 'D:\AI\models\Qwen3.6-27B-Q6_K.gguf'
  '--alias'; 'Qwen3.6-27B-Q6_K'
  '--host'; '127.0.0.1'
  '--port'; '8080'
  '--jinja'
  '--reasoning-format'; 'auto'
  '--reasoning'; 'on'
  '--ctx-size'; '32768'
  '--parallel'; '1'
  '--cache-type-k'; 'q8_0'
  '--cache-type-v'; 'q8_0'
  '--flash-attn'; 'on'
  '--n-gpu-layers'; 'auto'
  '--fit'; 'on'
  '--fit-target'; '256'
  '--no-mmproj'
  '--no-webui'
  '--no-agent'
  '--offline'
)
& 'D:\AI\llama.cpp\llama-server.exe' @qwenArgs
```

Это профиль полноценного агентного опыта. Не добавляйте ограничения короткой дымовой проверки:

```text
--reasoning-budget 32
--n-predict 96
```

Они искусственно обрезают вывод и не проверяют способность пройти длинную агентную задачу.

Признаки готовности:

- процесс остаётся запущенным;
- журнал сообщает о прослушивании `127.0.0.1:8080`;
- в другом окне PowerShell отвечает `/v1/models`;
- точный идентификатор равен `Qwen3.6-27B-Q6_K`.

Проверка без вывода `.env`:

```powershell
Invoke-RestMethod -Method Get -Uri 'http://127.0.0.1:8080/v1/models'
```

Проверенные измерения:

- готовность сервера: 18,75 с;
- полная модельная проверка: 85,02 с;
- пик VRAM: 23822 MiB;
- пик RAM: 65774972928 байт.

Это почти предел машины. Из 24455 MiB VRAM остаётся очень небольшой запас, а системная RAM приближается к полной ёмкости.

### Без сетевого обращения к модели

```powershell

```

Команда проверяет:

- работающий Docker;

```powershell
uv run python scripts/evaluate.py --task tasks/chess-terminal-move --evaluation tasks/chess-terminal-move/public_tests -v
```

Проверенный результат:

```text
exit code 1
FAIL_TO_PASS 0/1
PASS_TO_PASS 9/9
RESOLVED: no
```

Как читать результат:

- `FAIL_TO_PASS 0/1` — известный дефект воспроизведён;
- `PASS_TO_PASS 9/9` — прежнее поведение не разрушено в исходной точке;
- `RESOLVED: no` и код 1 — ожидаемый итог без исправления;
- контейнер успешно собрался и выполнил проверки; при штатном завершении этого запуска `with` удаляет его немедленно.

Не пытайтесь превратить этот исход в код 0 до того, как CodeAgent создаст проверяемый патч.

## 12. Ресурсная предполётная проверка

Перед одновременным запуском Qwen и Docker закройте тяжёлые программы и проверьте запас:

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object TotalVisibleMemorySize, FreePhysicalMemory
nvidia-smi --query-gpu=name,memory.total,memory.used,memory.free --format=csv
docker stats --no-stream
```

Не запускайте:

- Qwen и GPT-OSS одновременно;
- две партии одновременно;
- два программирующих опыта одновременно;
- проверку `local_tests` параллельно с полным агентным опытом.

Если появляется давление на RAM или VRAM:

1. остановите опыт штатно;
2. убедитесь, что контейнер удалён;
3. закройте тяжёлые программы;
4. при необходимости уменьшите `--ctx-size`;
5. запишите новый профиль как отдельное условие;
6. заново выполните `assignment-doctor`;
7. заново выполните `scripts/check_local_model.py`;
8. повторите сам опыт и не смешивайте его артефакты с профилем 32768.

Проверка на 32768 не доказывает работу на 64K или 128K. Любое увеличение требует нового измерения готовности, совместимости, RAM и VRAM.

## 13. Рабочая точка шахматной песочницы

Для ручного запуска местной шахматной службы используется:

```powershell
$chessSandboxArgs = @(
  'assignment-chess-local'
  '--task'; 'tasks/chess-terminal-move'
  '--sandbox-timeout'; '1800'
)
uv run @chessSandboxArgs
```

Без патча служба запускает исходное приложение и пригодна для проверки инфраструктуры до завершающего дефектного хода. После появления `artifacts/fix.patch` добавьте:

```powershell
$chessSandboxArgs = @(
  'assignment-chess-local'
  '--task'; 'tasks/chess-terminal-move'
  '--patch'; 'artifacts/fix.patch'
  '--sandbox-timeout'; '1800'
)
uv run @chessSandboxArgs
```

Команда печатает адрес вида:

```text
http://127.0.0.1:<случайный-порт>
```

Не закрывая окно песочницы, откройте второе окно PowerShell, подставьте напечатанный адрес и проверьте службу:

```powershell
$chessUrl = 'http://127.0.0.1:<случайный-порт>'
$health = Invoke-RestMethod -Method Get -Uri "$chessUrl/health"
if ($health.status -ne 'ok') {
  throw "Неожиданный ответ /health: $($health | ConvertTo-Json -Compress)"
}
$state = Invoke-RestMethod -Method Get -Uri "$chessUrl/api/state"
$health
$state | Select-Object status, turn, game_over
```

- **Ожидаемый ответ `/health`:** поле `status` равно `ok`.
- **Ожидаемое начальное состояние:** запрос `/api/state` возвращает объект с полями `status`, `turn` и `game_over`; до партии `game_over` имеет значение `False`.
- **Отклонение:** HTTP-ошибка, другой ответ готовности или отсутствие полей состояния означает, что рабочая точка не подтверждена.

Остановите её `Ctrl+C`. Штатный выход из управляющего блока закрывает клиент и немедленно удаляет контейнер; после аварийного обрыва действует отложенная страховка `--rm`.

## 14. Порядок штатной остановки

Если идёт полный агентный запуск:

1. дождитесь его завершения либо один раз нажмите `Ctrl+C` в окне запуска;
2. дайте обработчику `finally` сохранить траекторию и удалить контейнер;
3. проверьте отсутствие контейнеров проекта;
4. только затем остановите llama.cpp сочетанием `Ctrl+C`;
5. после смены модели измените `.env` и запустите другой сервер.

Проверка контейнеров:

```powershell
docker ps -a --filter 'label=assignment.local-environment=true'
```

В обычном состоянии после завершения список пуст.

Если управляющий процесс был аварийно убит, контейнер обычно завершит `sleep` по `deployment_timeout` и будет удалён благодаря `--rm`. При недоступном или повреждённом Docker сначала восстановите доступ к демону, затем проверьте остаток. Для адресного ручного удаления допустим только один сверенный контейнер задания:

```powershell
$containerIds = @(docker ps -aq --filter 'label=assignment.local-environment=true')
if ($LASTEXITCODE -ne 0) {
  throw 'Не удалось получить список контейнеров задания.'
}
if ($containerIds.Count -ne 1) {
  throw "Ожидался ровно один контейнер задания; найдено: $($containerIds.Count)."
}
$containerId = [string]$containerIds[0]
if ([string]::IsNullOrWhiteSpace($containerId)) {
  throw 'Docker вернул пустой идентификатор контейнера.'
}
$containerLabel = docker inspect --format '{{ index .Config.Labels "assignment.local-environment" }}' $containerId
if ($LASTEXITCODE -ne 0) {
  throw "Не удалось прочитать метку контейнера $containerId."
}
$containerLabel = ([string]$containerLabel).Trim()
if ($containerLabel -ne 'true') {
  throw "Контейнер $containerId не имеет требуемой метки задания."
}
$containerName = docker inspect --format '{{.Name}}' $containerId
if ($LASTEXITCODE -ne 0) {
  throw "Не удалось прочитать имя контейнера $containerId."
}
$containerName = ([string]$containerName).Trim()
if ([string]::IsNullOrWhiteSpace($containerName)) {
  throw "Docker вернул пустое имя контейнера $containerId."
}
Write-Host "Сверьте перед удалением: $containerName  $containerId"
$confirmedId = Read-Host 'Для удаления повторно введите показанный идентификатор'
if ($confirmedId -ne $containerId) {
  throw 'Идентификатор не подтверждён; удаление отменено.'
}
docker rm -f $containerId
if ($LASTEXITCODE -ne 0) {
  throw "Не удалось удалить контейнер $containerId."
}
```

Не используйте массовое удаление всех контейнеров Docker.

## 15. Восстановление при сбое

Этот раздел применяется только после того, как проверка выявила конкретную неисправность.

### Docker Desktop не отвечает

1. Убедитесь, что Docker Desktop запущен.
2. Повторите `docker version`.
3. Проверьте, что выбран движок Linux.
4. Проверьте файл `D:\DockerData\DockerDesktop.vhdx`.
5. Перезапустите Docker Desktop штатно.
6. Повторите быстрые тесты и `assignment-doctor --offline`.

Переустановка не является первым действием.

### Dr.Web блокирует обновление HOSTS

Проверенный симптом: Docker Desktop застревает на `refreshing DNS hosts`, а журнал сообщает об отказе доступа к `C:\Windows\System32\drivers\etc\hosts`.

1. Откройте журнал событий Dr.Web и найдите блокировку для точного пути `C:\Program Files\Docker\Docker\com.docker.service`.
2. Проверьте цифровую подпись файла:

```powershell
$dockerService = 'C:\Program Files\Docker\Docker\com.docker.service'
Get-AuthenticodeSignature -FilePath $dockerService | Select-Object Status, StatusMessage, SignerCertificate
```

1. Только если `Status` равен `Valid` и событие относится к этому точному файлу, разрешите в Dr.Web этому подписанному исполняемому файлу требуемое изменение HOSTS.
2. Не отключайте защиту, не создавайте широкое исключение для диска C:, каталога Windows или всего Docker и не редактируйте `hosts` вручную как основное решение.
3. Перезапустите Docker Desktop и проверьте:

```powershell
docker version
$hostsPath = 'C:\Windows\System32\drivers\etc\hosts'
Select-String -LiteralPath $hostsPath -Pattern '# Added by Docker Desktop', 'host.docker.internal', 'gateway.docker.internal', '# End of section'
```

1. Убедитесь, что сервер Docker отвечает, штатная секция Docker присутствует в `hosts`, а в Dr.Web не появилось нового события отказа для `com.docker.service`.



### Закреплённый исходник не прошёл проверку

```powershell
git submodule status
git -C chess_app status --short
git -C chess_app rev-parse HEAD
```

Не исправляйте приложение и не очищайте его вслепую. Если подмодуль отсутствует, восстановите только его получение:

```powershell
git submodule update --init
```

Если он изменён, сначала установите происхождение изменений. Заплатка задания должна применяться в контейнере, а не храниться в местном `chess_app`.

### Проектное окружение повреждено

```powershell
uv sync
uv run pytest tests/test_infrastructure.py tests/test_smoke.py
```

`uv sync` приводит `.venv` к `pyproject.toml` и файлу блокировки. Не редактируйте установленные пакеты вручную.

### Порт 8080 занят или сервер не отвечает

```powershell
Get-NetTCPConnection -LocalAddress 127.0.0.1 -LocalPort 8080 -ErrorAction SilentlyContinue
Get-Process -Name 'llama-server' -ErrorAction SilentlyContinue
```

Не запускайте второй сервер поверх первого. Остановите только известный процесс llama.cpp, затем повторите запуск нужной модели.

### `doctor` не находит модель

Причина обычно одна из трёх:

- псевдоним `--alias` не совпадает с `OPENAI_MODEL`;
- `.env` всё ещё указывает на предыдущую модель;
- запущен другой сервер.

Исправьте расхождение, затем повторите:

```powershell
uv run assignment-doctor
uv run python scripts/check_local_model.py
```



### Не хватает памяти

Не увеличивайте файл подкачки и лимиты Docker как первое действие. Сначала:

- оставьте одну модель;
- закройте тяжёлые программы;
- прекратите параллельные опыты;
- проверьте, нет ли оставшегося контейнера;
- уменьшите контекст и полностью перепроверьте новый профиль.
