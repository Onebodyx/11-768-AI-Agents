Архитектура каркаса агента: кто, что и куда передаёт

Шпаргалка к части 1 задания 1 (разделы 2–4 и договоры TODO 1.1–1.4). Схема показывает сущности каркаса, границу между Windows и Linux-контейнером и движение данных. Наведите указатель на любой блок или стрелку — появится пояснение. Справа — пошаговый проигрыватель: выберите сценарий и листайте шаги кнопками или стрелками клавиатуры. Здесь описаны только договоры поведения из руководства: готовых решений TODO нет.

Agent и CodeAgent в двух словах

Agent base.py — общая часть любого агента

Умеет:
  • хранить активную историю сообщений;
  • собирать следующий запрос (build_prompt());
  • обращаться к модели и вести журнал (query_language_model());
  • повторять цикл «запрос → действия → наблюдения» (run()) и следить за пределом шагов;
  • загружать навыки и сохранять траекторию в finally.
Не знает (и не должен знать):
  • какие инструменты существуют и как их исполнять;
  • когда предметная задача решена.

CodeAgent code_agent.py — наследник для программных задач

Получает весь цикл Agent готовым и добавляет только своё:
  • содержание запросов: роль агента, порядок исследования и проверки, сведения о Linux-контейнере, полную постановку задачи;
  • инструменты execute (команда в /testbed) и send_message (сообщить о завершении);
  • распределитель execute_tool_calls(): по имени вызова выбирает обработчик и возвращает наблюдение;
  • правило завершения: успешный send_message ставит finished=True.

Что такое «наследник»

Наследник — класс, созданный на основе другого класса. Он автоматически получает всё поведение родителя и дописывает или уточняет только недостающие части.

Аналогия: Agent — общий регламент экзамена (выдать задание, выслушать ответ, записать в протокол, следить за временем). CodeAgent — конкретный предмет: какие действия разрешены экзаменуемому и что считается сдачей.

Поэтому в части 3 ChessAgent тоже унаследует тот же цикл Agent, но добавит шахматные указания и инструменты.

Как читать схему

Windows — доверенная зона: PowerShell, llama.cpp, управляющий Python-код, Docker Desktop Linux-контейнер Docker — недоверенная зона: здесь исполняются действия модели участник текущего шага проигрывателя

Памятки

  

    

      
Роли сообщений

      
    
        
  • system — постоянные правила, роль агента, сведения о среде, краткий каталог навыков. Первое сообщение.
    • 
        
  • user — исходная задача или короткое указание продолжить.
    • 
        
  • assistant — полный ответ модели: текст, служебные поля и список tool_calls.
    • 
        
  • tool — наблюдение после исполнения одного вызова. Поле tool_call_id связывает его с вызовом.
    • 
      

      
Сообщение tool создаёт каркас, а не модель.

    

    

      
Из чего строится следующий запрос


следующий запрос
  = system

      assistant_1(tool_call=A)

build_prompt() возвращает новую независимую копию и ничего не дописывает. Каждое сообщение в истории хранится один раз, в порядке появления.

    

    

      
Рабочая память ≠ журнал

      

        

          
Активная история

          
    
            
  • нужна, чтобы продолжить диалог;
    • 
            
  • из неё строится следующий запрос;
    • 
            
  • без повторов system и user(task).
    • 
          

        

        

          
Журналы

          
    
            
  • api_prompts — снимки отправленных запросов;
    • 
            
  • api_responses — полные ответы API;
    • 
            
  • нужны для разбора, в запрос не входят.
    • 
          

        

      

    

    

      
Предел шагов step_limit

      
Один шаг — один успешный ответ модели. Счётчик steps_taken растёт внутри query_language_model().

      
    
        
  • 0 — модель не вызывается ни разу, сразу StepLimitError;
    • 
        
  • 1 — ровно один запрос; его вызовы исполняются полностью;
    • 
        
  • N — N-й ответ исполняется полностью, запрос N+1 отклоняется до обращения к API.
    • 
      

    

    

      
Наблюдение или остановка?

      

        

          
Становится наблюдением tool

          
    
            
  • повреждённый JSON в arguments;
    • 
            
  • не объект, лишнее или пропущенное поле, неверный тип;
    • 
            
  • неизвестный инструмент или навык;
    • 
            
  • вызов после finished=True;
    • 
            
  • ненулевой returncode.
    • 
          

        

        

          
Останавливает запуск

          
    
            
  • ошибка формата навыков — ValueError при загрузке;
    • 
            
  • исчерпан предел — StepLimitError;
    • 
            
  • сбой API или мёртвый контейнер.
    • 
          

          
finally выполняется в обоих случаях.
