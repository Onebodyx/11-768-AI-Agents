> **Воспроизводимая официальная версия:** [коммит `67498d8`](https://github.com/cmu-agents/assignment-1/tree/67498d87e36f7b45a2a4ce82d65d1139fb6a51c0)
> **Официальное условие на этой версии:** [ASSIGNMENT.md](https://github.com/cmu-agents/assignment-1/blob/67498d87e36f7b45a2a4ce82d65d1139fb6a51c0/ASSIGNMENT.md)

## Учебный договор

В этом варианте задания нет требований к университетской учётной записи, сроку сдачи, внешнему поставщику вычислений или платному API. Полный рабочий путь местный:

1. пользователь запускает команды в Windows PowerShell;
2. `llama-server.exe` работает непосредственно в Windows и слушает только `127.0.0.1:8080`;
3. каркас обращается к нему через OpenAI-совместимый API `http://127.0.0.1:8080/v1`;
4. команды программирующего агента и порождённый моделью Python выполняются только в эфемерном Linux-контейнере Docker;
5. исходники задачи находятся в контейнере по неизменному пути `/testbed`;
6. контейнер ограничен по возможностям и ресурсам; штатный `with`/`finally` удаляет его немедленно, а `--rm` страхует аварийный обрыв отложенной очисткой после срока жизни при доступном Docker.

Пользователь не пишет исходники вручную. Каждое изменение в `src/assignment/agent/` оформляется как небольшое точное поручение программирующему ИИ-агенту. Пользователь:

- выполняет настройки и команды PowerShell;
- до правки требует объяснить договор поведения, файлы и способ проверки;
- просматривает состав изменений;
- запускает проверки самостоятельно;
- изучает траектории, патчи и результаты;
- завершает этап только тогда, когда может объяснить изменение без пересказа ответа агента.

Это руководство намеренно не содержит полных тел TODO, готовых запросов методов, исправления шахматного дефекта и эталонного `fix.patch`.

## Что уже готово, а что ещё предстоит сделать

В адаптированном `assignment-1` местная инфраструктура уже реализована и проверена:

- `Environment` создаёт эфемерный Linux-контейнер Docker;
- рабочий каталог агента остаётся `/testbed`;
- публичный договор `Environment.execute` сохранён;
- образ строится из закреплённой местной копии исходников;
- шахматная служба доступна через случайный порт только на `127.0.0.1`;
- обязательный код очистки выполняет немедленный `stop`/`rm` при штатном или обработанном выходе; `--rm` удаляет контейнер после `deployment_timeout`, если управляющий процесс оборван и Docker доступен.


Это не отказ Docker или модели. Падения обозначают ещё не реализованные договоры частей 1–3.

## Последовательность ворот

Каждый более дорогой по времени и ресурсам этап начинается только после предыдущего. Команды выполняются из корня `assignment-1`.

### Ворота 1. Быстрые проверки инфраструктурного слоя

```powershell
uv run pytest tests/test_infrastructure.py tests/test_smoke.py
```

Проверенный результат:

```text
3 passed
```

Эти проверки не запускают контейнер и не зависят от заполнения TODO.

### Ворота 2. Диагностика Docker, исходников и настроек

Сначала без обращения к серверу модели:

```powershell
uv run assignment-doctor --offline
```

При работающем llama.cpp:

```powershell
uv run assignment-doctor
```

Первая команда проверяет Docker, закреплённый исходник и поля настроек, включая обязательный путь `/v1` в `OPENAI_BASE_URL`. Корневой URL диагностика отвергает. Вторая дополнительно запрашивает `/v1/models` и требует точного совпадения `OPENAI_MODEL` с псевдонимом запущенной модели.

### Ворота 3. Проверка совместимости модели

```powershell
uv run python scripts/check_local_model.py
```

Проверяются не только доступность и обычный текстовый ответ, но и обязательные свойства каркаса:

- один вызов инструмента;
- два вызова в одном ответе;
- строгая схема;
- непустые идентификаторы;
- параметры `reasoning_effort` и `max_completion_tokens`;
- поля `usage`.

Qwen3.6-27B-Q6_K прошла эту проверку полностью. GPT-OSS-20B-MXFP4 прошла всё, кроме двух одновременных вызовов: в этом случае она вернула только `add`. Это ограничение одного проверенного режима, а не запрет всех инструментов.

### Ворота 4. Настоящие местные контейнеры

```powershell
uv run pytest local_tests -m local -v
```

Проверенный результат:

```text
61 passed
```

Здесь действительно создаются Linux-контейнеры Docker. Набор проверяет ограничения, порты, тайм-ауты, сборку образа, шахматную службу, передачу пользовательских `argv` и `env` обычного `exec` JSON-ом через stdin вместо аргументов `docker.exe`, а также `--init`, немедленную штатную очистку и отложенную страховку `--rm`.

### Ворота 5. Полный опыт

До реализации TODO зафиксируйте исходный дефект прямой проверкой без патча:

```powershell
uv run python scripts/evaluate.py --task tasks/chess-terminal-move --evaluation tasks/chess-terminal-move/public_tests -v
```

Ожидаемый и уже проверенный исход:

```text

FAIL_TO_PASS 0/1
PASS_TO_PASS 9/9
RESOLVED: no
```

Это доказательство воспроизведения дефекта в чистой среде. Инфраструктура при таком исходе работает правильно.

После реализации соответствующего этапа полный опыт означает:

- настоящий запуск агента на Qwen;
- отдельную траекторию;

- прохождение целевой и регрессионной проверок;
- отсутствие оставшегося контейнера.

## Официальная и местная среда

Официальное условие закреплено ссылкой на коммит и полезно как спецификация TODO. Исполняемый путь этого руководства отличается следующим образом.

- **Внешняя песочница в исходном курсе:** Modal.
  **Местный эквивалент:** Docker Desktop, Linux/amd64, Hyper-V.
- **Удалённое хранилище исходников:** внешняя песочница.
  **Местный эквивалент:** чистый образ и эфемерный контейнер с тем же `/testbed`.
- **Внешняя модель из курса:** назначенный поставщик.
  **Местный эквивалент:** нативный `llama-server.exe` на `127.0.0.1`.
- **Секретный ключ поставщика:** внешний секрет.
  **Местный эквивалент:** `OPENAI_API_KEY=local-dummy`, непустое служебное значение SDK, не являющееся секретом.
- **Публичный или зашифрованный туннель:** внешний сетевой адрес.
  **Местный эквивалент:** случайный порт, опубликованный только на `127.0.0.1`.
- **Официальные имена моделей:** часть первоначальной постановки опыта.
  **Местный опыт:** `Qwen3.6-27B-Q6_K` и `gpt-oss-20b-MXFP4`.
- **Сдача и оценка:** административная часть курса.
  **Местная цель:** воспроизводимые свидетельства и понимание архитектуры.

Пакеты `modal` и `swe-rex[modal]` пока остаются в `pyproject.toml`, чтобы не ломать нетронутые исторические проверки. Для рабочего пути не нужны ни служба, ни учётные данные Modal. Точка `assignment-chess-modal` сохранена только как совместимый исторический псевдоним; рабочее имя — `assignment-chess-local`.

## Безопасностный договор

Местная песочница не равна обычному запуску процесса на компьютере.

- Контейнер использует сеть `bridge`.
- Каталоги хоста не подключаются через bind mount.
- Сокет Docker внутрь не передаётся.
- Домашний каталог, `.env` и иные секреты не подключаются.
- Устройства, включая GPU, контейнеру не передаются.
- Возможности Linux сбрасываются через `cap-drop=ALL`.
- Включено `no-new-privileges`.
- Включён `--init`, чтобы PID 1 собирал завершившиеся дочерние процессы.
- Включён `--rm` для отложенного удаления после `deployment_timeout`, если управляющий процесс оборвался и демон Docker доступен.
- Число процессов ограничено 512.
- Контейнер получает не более 8 CPU и 8 GiB RAM.
- Порты при необходимости назначаются Docker случайно и связываются только с `127.0.0.1`.
- Пользовательские команда и `env` обычного `exec` передаются контейнерному исполнителю через stdin, а не попадают в аргументы процесса `docker.exe` на Windows.
- Штатный `with`/`finally` вызывает немедленные `stop` и адресное удаление. При недоступном или повреждённом Docker результат нужно проверить и при необходимости удалить только сверенный контейнер вручную.

Никогда не исполняйте в Windows код, созданный моделью. Инструмент `execute` должен вызывать `Environment.execute`, а `run_python` — контейнерный `/opt/assignment/sandbox_python.py`.

## Ресурсные границы

Проверенная Qwen с контекстом 32768 почти исчерпывает компьютер:

- готовность сервера: 18,75 с;
- полная проверка совместимости: 85,02 с;
- пик VRAM: 23822 MiB из 24455 MiB;
- пик RAM: 65774972928 байт.

Проверенная GPT-OSS заметно легче:

- готовность: 8,55 с;
- проверка: 6,44 с;
- пик VRAM: 13250 MiB;
- пик RAM: 56598880256 байт.

Практические следствия:

1. держите загруженной только одну модель;
2. закройте тяжёлые программы перед одновременной работой модели и Docker;
3. проверьте свободную RAM и VRAM перед полным опытом;
4. не запускайте несколько агентных опытов параллельно;
5. при давлении на память уменьшите контекст модели, затем заново выполните `assignment-doctor`, `check_local_model.py` и сам опыт;
6. новое значение контекста считается новым профилем и должно быть записано в отчёте;
7. не обещайте 64K или 128K без отдельного измерения совместимости и пиков памяти.

## Артефакты как ориентир полноты

Официальный перечень полезен не как форма сдачи, а как карта доказательств:

- `fix.patch` показывает результат программирующего агента;
- `part1-trajectory.json` показывает путь к этому результату;
- пары патча и траектории со сжатием и без него позволяют сравнить память;
- четыре пары шахматных траекторий и результатов подтверждают опыт 2 × 2;
- `token-usage-analysis.md` отделяет измерения от интерпретаций;
- `observation-experiment.md` фиксирует метод подсчёта и ограничения;
- `part3-python-skill-trajectory.json` доказывает совместную работу навыка, моделирования, программы и живого хода;
- `AI_USAGE.md` фиксирует, какие ИИ-агенты меняли код или анализировали данные и как проверялся их результат.

Имена местных опытов должны отражать фактические модели. Не переименовывайте Qwen в официальную модель курса ради совпадения с первоначальным шаблоном.

Файл считается свидетельством только тогда, когда:

- он относится к записанным команде, модели и профилю;
- JSON разбирается;
- патч применяется к свежей исходной точке;
- результат подтверждается проверками;
- траектория согласуется с патчем или состоянием партии;
- в нём нет содержимого `.env` и иных секретов.

## Рабочий цикл одного TODO

1. Прочитайте относящиеся к TODO условие, заготовку и открытые проверки.
2. Своими словами запишите входы, выходы, изменяемое состояние и инварианты.
3. Дайте программирующему агенту одно узкое поручение.
4. Потребуйте до правки назвать затрагиваемые файлы и способ проверки.
5. После правки просмотрите изменения.
6. Запустите узкую проверку из PowerShell.
7. Передайте агенту точный вывод отказа, если он есть; не разрешайте ослаблять проверку.
8. Выполните более широкие ворота.
9. Просмотрите траекторию или патч, а не только итоговое сообщение агента.
10. Объясните, почему результат следует из наблюдений.
