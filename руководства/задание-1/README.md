## Для чего нужно это руководство

Задание предлагает не просто дописать несколько функций. Оно последовательно проводит через основные уровни агентной системы:

1. построение общего цикла ReAct и программирующего агента;
2. управление растущей историей;
3. перенос того же каркаса в шахматную среду;
4. подключение обычных и программных инструментов;
5. применение навыков и проведение воспроизводимых опытов.

Цель руководства — помочь понять ответственность каждого слоя, увидеть зависимости между частями и самостоятельно прийти к реализации. Здесь намеренно нет:

- полных тел методов из задания;
- готового системного запроса;
- эталонного диспетчера инструментов;
- исправления дефекта шахматного приложения;
- заполненных отчётов и готовых выводов;
- траектории, которую можно сдать вместо собственной.

Такое ограничение соответствует учебной цели курса: студент отвечает за каждую строку кода и должен уметь объяснить решение.

## Как связаны части

```text
Общий Agent и цикл ReAct
          |
          +-----------------------------+
          |                             |
          v                             v
      CodeAgent                     ChessAgent
          |                             ^
          | исправляет приложение       |
          v                             |
       fix.patch -----------------------+
          |
          v
  задача SWE-bench
  с полным/сжатым контекстом
```

Ключевая архитектурная идея: `Agent` содержит предметно-независимый цикл, а `CodeAgent` и `ChessAgent` определяют свои инструменты и способ их исполнения. Если приходится копировать цикл между подклассами, граница ответственности выбрана неверно.

## Рекомендуемый порядок работы

1. Прочитайте [обзор и подготовку](00-обзор-и-подготовка.md).
2. Выполните бесплатную настройку и зафиксируйте исходное состояние тестов.
3. Проходите [часть 1](01-программирующий-агент.md) небольшими шагами:
   - состояние и запрос;
   - инструменты;
   - цикл;
   - навыки;
   - только затем платный запуск агента.
4. Убедитесь, что `fix.patch` воспроизводимо проходит `make check-part1`.
5. После лекции 3 переходите к [части 2](02-сжатие-контекста.md).
6. Сохраните оба опыта с Django под разными именами и самостоятельно сравните их.
7. Переходите к [части 3](03-шахматный-агент.md) по слоям:
   - один живой ход;
   - сравнительный опыт;
   - безопасная симуляция;
   - программный инструмент;
   - навык.
8. Перед сдачей сверьте весь список артефактов и создайте `AI_USAGE.md`.

На каждом шаге сначала запускайте узкую бесплатную проверку, затем весь `make test`, и только после этого — команду, создающую песочницу Modal или обращающуюся к LLM.

## Карта зависимостей TODO

```text
1.1.a  состояние + build_prompt
  |
  +--> 1.2 общий цикл ReAct -----------+
  |                                    |
  +--> 2.1 и 2.2 сжатие контекста      |
  |                                    |
  +------------------------------> ChessAgent

1.1.b запросы CodeAgent
1.3 инструменты CodeAgent --> запуск CodeAgent
1.4 навыки -----------------> fix.patch
                                  |
                                  v
                             часть 3

3.1 play_move --> четыре опыта
3.3 simulate_move --> 3.4 run_python --> 3.5 навык
```

Зависимости имеют практическое значение. Например, часть 3 применяет патч из части 1 к свежей копии шахматного приложения. Если патч неполон или зависит от загрязнённого рабочего каталога, шахматный агент не запустится независимо от качества его инструментов.

## Оценивание

Задание оценивается из 100 баллов:

- часть 1 — 30;
- часть 2 — 28;
- часть 3 — 40;
- полнота и корректность архива — 2.

Критерии независимы. Неудачный вероятностный запуск модели не обнуляет баллы за корректную схему инструмента или обработку ошибок. Поэтому храните доказательства по каждому разделу отдельно: тесты, патчи, траектории, результаты игр и отчёты.

Открытые тесты не доказывают полную корректность. Закрытые проверки дополнительно рассматривают:

- очистку ресурсов после исключений;
- повреждённые и повторяющиеся навыки;
- несколько шахматных вызовов в одном ответе;
- сетевые сбои;
- согласованность артефактов;
- воспроизводимость патча;
- настоящую интеграцию с Modal.

## Известные уточнения к проверенной версии

Руководство привязано к указанному коммиту, потому что условие и код могут обновляться.

### Прямой запуск `assignment-play-chess`

В разделах 3.4 и 3.5 условия приведены сокращённые команды. В текущем `cli.py` обязательны:

- `--patch`;
- `--trajectory`.

Параметр `--result` имеет значение по умолчанию, но для отдельных опытов его лучше задавать явно, чтобы один запуск не перезаписал результат другого. Готовые цели `make run-chess-agent` и `make run-obs-*` уже передают нужные пути.

### Проверки `move` и `fen`

В тексте TODO 3.1.b среди ошибок `play_move` упомянут отсутствующий или нестроковый `fen`. Однако `play_move` принимает только `move`; `fen` относится к `simulate_move`. Ориентируйтесь на схему конкретного инструмента, серверный маршрут и открытые тесты.

### Команды Modal

Если Modal установлен как зависимость проекта через `uv`, надёжнее выполнять диагностические команды как `uv run modal ...`, чтобы использовалась версия из окружения проекта.

Перед работой проверяйте, не появились ли новые коммиты или исправления условия. Не переносите изменения вслепую: сначала сравните их с версией, на которой создавались ваши артефакты.

## Правила работы с подсказками

Полезная подсказка отвечает на вопросы:

- какое состояние должен сохранять слой;
- какой контракт он обязан соблюдать;
- какие ошибки должен переживать;
- как доказать, что он работает.

Неполезная подсказка просто даёт тело функции. Она ускоряет набор текста, но скрывает важные решения: границы шага, порядок сообщений, восстановление после ошибок и согласованность журналов.

Для каждого TODO используйте цикл:

1. своими словами сформулировать контракт;
2. перечислить входы, выходы и изменяемое состояние;
3. назвать инварианты;
4. придумать успешный и несколько ошибочных случаев;
5. реализовать минимальный шаг;
6. запустить узкие тесты;
7. объяснить результат без чтения собственного кода.
